## 1. Overview

A single-user app that logs strength workouts and generates the next workout, optimized for hypertrophy.

- **Database** stores profile, exercises (with muscle map), training blocks, prescribed sets, and performed sets.
- **Engine** (deterministic code) computes each session's loads, reps, sets, and RIR from the block template and history, and emits flags.
- **Agent** (LLM, evidence-based hypertrophy coach, §12) plans each 4-week block and reviews sessions that need interpretation.

Core model the rules implement: growth is driven mainly by **weekly hard sets per muscle** (fractional count), taken to **0–3 RIR**. Load (5–30 reps), frequency, split, order, periodization and tempo are secondary and used to fit volume into the schedule.

### Non-goals (v1)
Multi-user/auth, cardio, supersets/drop sets, CSV import, nutrition, wearables, daily readiness tracking, charts, conversational onboarding, tempo tracking, within-block RIR ramps.

## 2. Locked decisions

| # | Decision | Rule |
|---|---|---|
| D1 | Agent scope | Agent plans a fixed 4-week block (3 build weeks + 1 deload). Sessions inside the block are generated by the engine. Re-plan only at block end or on a trigger (§6.1). |
| D2 | Code vs. LLM | Code: progression, e1RM, rounding, caps, exclusions, volume counting, validation, flags. LLM: split, exercise selection, set/rep scheme, target RIR, interpreting notes/pain, rationale text. |
| D3 | Prescribed vs. actual | Every set row stores both prescribed and actual values. |
| D4 | Agent I/O | Agent reads precomputed summaries (§6.3), returns JSON validated against a schema (§6.4). Agent never writes to the DB; app code writes after validation. |
| D5 | Scope | Single user, one platform, SQLite. |
| D6 | Privacy | GitHub holds code, docs, prompts and synthetic test data only. No personal training information ever reaches GitHub (files, history, commit messages, PRs, issues, Actions logs). Enforced in layers (§13.2). |

## 3. Stack (defaults, reversible)

- Python 3.12, stdlib `sqlite3`, `pydantic` v2 for agent I/O schemas, `pytest`.
- LLM: Claude via the Anthropic SDK, structured output through tool use. Model name and prompt version stored per call.
- Canonical unit: kg. Display unit from profile.
- Data directory: `$COACH_DATA_DIR` (default `~/.workout-coach/`), **outside the repo**. Holds `coach.db`, exports, and any debug logs. The app refuses to start if the resolved data directory is inside a git work tree.
- Secrets: `ANTHROPIC_API_KEY` from the environment or `$COACH_DATA_DIR/.env`; never in the repo.

## 4. Data model (SQLite)

```sql
CREATE TABLE profile (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  goal TEXT NOT NULL CHECK (goal IN ('strength','hypertrophy','general')),
  training_age_months INTEGER NOT NULL,
  days_per_week INTEGER NOT NULL CHECK (days_per_week BETWEEN 2 AND 6),
  session_minutes INTEGER NOT NULL,
  display_unit TEXT NOT NULL DEFAULT 'kg' CHECK (display_unit IN ('kg','lb')),
  priority_muscles TEXT,              -- JSON array of muscle names (§4 muscle list), optional
  sex TEXT, birth_year INTEGER, height_cm REAL, bodyweight_kg REAL,
  updated_at TEXT NOT NULL
);

CREATE TABLE equipment (
  id INTEGER PRIMARY KEY,
  name TEXT UNIQUE NOT NULL,          -- barbell, dumbbell, cable, machine, pullup_bar, bench, rack
  available INTEGER NOT NULL DEFAULT 1,
  increment_kg REAL                   -- smallest load jump (dumbbell: per hand)
);

CREATE TABLE exercise (
  id INTEGER PRIMARY KEY,
  name TEXT UNIQUE NOT NULL,
  movement_pattern TEXT NOT NULL CHECK (movement_pattern IN
    ('squat','hinge','h_push','v_push','h_pull','v_pull','lunge','core','isolation')),
  equipment_id INTEGER REFERENCES equipment(id),
  load_type TEXT NOT NULL CHECK (load_type IN ('external','bodyweight')),
  unilateral INTEGER NOT NULL DEFAULT 0,
  stretch_bias INTEGER NOT NULL DEFAULT 0   -- 1 = loads the muscle at long length; agent tie-breaker only (E-low)
);

CREATE TABLE exercise_muscle (        -- fractional volume map (E-mod: Pelland 2025)
  exercise_id INTEGER NOT NULL REFERENCES exercise(id),
  muscle TEXT NOT NULL CHECK (muscle IN ('chest','back','quads','hamstrings','glutes',
         'side_delts','rear_delts','front_delts','biceps','triceps','calves','abs')),
  weight REAL NOT NULL CHECK (weight IN (1.0, 0.5)),
  PRIMARY KEY (exercise_id, muscle)
);

CREATE TABLE exercise_alias (
  alias TEXT PRIMARY KEY COLLATE NOCASE,
  exercise_id INTEGER NOT NULL REFERENCES exercise(id)
);

CREATE TABLE limitation (             -- injuries AND disliked exercises
  id INTEGER PRIMARY KEY,
  description TEXT NOT NULL,
  excluded_pattern TEXT,              -- e.g. 'v_push'
  excluded_exercise_id INTEGER REFERENCES exercise(id),
  active INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL
);

CREATE TABLE baseline (               -- onboarding self-reports
  id INTEGER PRIMARY KEY,
  exercise_id INTEGER NOT NULL REFERENCES exercise(id),
  weight_kg REAL NOT NULL,
  reps INTEGER NOT NULL,
  rir INTEGER,
  reported_at TEXT NOT NULL
);

CREATE TABLE agent_call (             -- audit + reproducibility
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('block_plan','session_review')),
  model TEXT NOT NULL,
  prompt_version TEXT NOT NULL,
  input_json TEXT NOT NULL,
  output_json TEXT,
  status TEXT NOT NULL CHECK (status IN ('accepted','rejected','error')),
  errors TEXT,
  warnings TEXT,                      -- non-blocking validator output (§6.5)
  created_at TEXT NOT NULL
);

CREATE TABLE block (
  id INTEGER PRIMARY KEY,
  start_date TEXT NOT NULL,
  weeks INTEGER NOT NULL DEFAULT 4,
  deload_week INTEGER NOT NULL DEFAULT 4,
  status TEXT NOT NULL CHECK (status IN ('active','completed','abandoned')),
  rationale TEXT,
  agent_call_id INTEGER REFERENCES agent_call(id)
);

CREATE TABLE block_slot (             -- fixed template for the block
  id INTEGER PRIMARY KEY,
  block_id INTEGER NOT NULL REFERENCES block(id),
  day_index INTEGER NOT NULL,         -- 0 .. days_per_week-1
  position INTEGER NOT NULL,
  exercise_id INTEGER NOT NULL REFERENCES exercise(id),
  sets INTEGER NOT NULL,
  rep_min INTEGER NOT NULL,
  rep_max INTEGER NOT NULL,
  target_rir INTEGER NOT NULL,
  UNIQUE (block_id, day_index, position)
);

CREATE TABLE session (
  id INTEGER PRIMARY KEY,
  block_id INTEGER NOT NULL REFERENCES block(id),
  week INTEGER NOT NULL,
  day_index INTEGER NOT NULL,
  date TEXT,
  status TEXT NOT NULL CHECK (status IN ('planned','completed','partial','skipped')),
  notes TEXT
);

CREATE TABLE set_entry (
  id INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES session(id),
  slot_id INTEGER REFERENCES block_slot(id),   -- NULL = unplanned exercise added by user
  exercise_id INTEGER NOT NULL REFERENCES exercise(id),
  set_index INTEGER NOT NULL,
  set_type TEXT NOT NULL DEFAULT 'working' CHECK (set_type IN ('warmup','working')),
  presc_weight_kg REAL,               -- NULL = calibration: user picks load
  presc_reps_min INTEGER,
  presc_reps_max INTEGER,             -- may exceed slot rep_max under rep-extension (§5.1)
  presc_rir INTEGER,
  load_modifier TEXT NOT NULL DEFAULT 'none'
    CHECK (load_modifier IN ('none','deload','gap','recalibrate','review_reduce')),
  actual_weight_kg REAL,
  actual_reps INTEGER,
  actual_rir INTEGER,
  pain INTEGER NOT NULL DEFAULT 0 CHECK (pain BETWEEN 0 AND 10),
  logged_at TEXT
);
```

Rules:
- Generating a session inserts its `set_entry` rows with `presc_*` and `load_modifier` filled and `actual_*` NULL.
- Logging fills `actual_*`. Edits to past entries are allowed; they affect only future generation, never past prescriptions.
- Seed ~40 common exercises with aliases, `stretch_bias`, and `exercise_muscle` rows. Every exercise must have ≥1 `exercise_muscle` row. Seed data is generic (exercise library only) and lives in the repo; everything else in the database is personal and lives only in `$COACH_DATA_DIR` (D6).

**`exercise_muscle` seed mapping** (PC/DC; squat/hip-thrust rows E-low, Plotkin 2023):

| Exercise family | 1.0 | 0.5 |
|---|---|---|
| Flat/incline press, push-up, dip | chest | triceps, front_delts |
| Chest fly | chest | — |
| Overhead press | front_delts | triceps, side_delts |
| Row, pulldown, pull-up | back | biceps, rear_delts |
| Squat, lunge, split squat | quads, glutes | — |
| Leg press, hack squat | quads | glutes |
| RDL, deadlift, good morning | hamstrings | glutes |
| Hip thrust | glutes | — (no hamstrings) |
| Leg curl, leg extension, calf raise, lateral raise, rear fly/face pull, curl, triceps extension, core | target muscle only | — |

## 5. Engine (deterministic)

### 5.0 Definitions
- **Tier** from `training_age_months`: `novice < 6`, `intermediate 6–35`, `advanced ≥ 36`. *(PC; cut-points DC)*
- **Effort class** (derived in code, no column; PC):
  - `HEAVY` = `squat` or `hinge` pattern with equipment = barbell.
  - `COMPOUND` = any other `squat, hinge, h_push, v_push, h_pull, v_pull, lunge`.
  - `ISOLATION` = `isolation, core`.
  - `stable` = equipment ∈ {machine, cable}.
- **Region**: `lower` = `squat, hinge, lunge`; all other patterns = `upper`.
- **`step_pct`** *(E-mod band: ACSM 2009 2–10%; split PC)*:

  | Tier | lower | upper (incl. ISOLATION) |
  |---|---|---|
  | novice | 7.5% | 5% |
  | intermediate / advanced | 5% | 2.5% |

- **`round_load(x)`** = round **down** to the exercise's equipment `increment_kg`.
- **`rir_eff`** = `clamp(actual_rir ?? 0, 0, 5)`. *(E-mod: lifters underpredict RIR by ~1 rep, Halperin 2022)*
- **`e1RM(set)`** = `w × (1 + (reps + rir_eff)/30)`; if `reps + rir_eff = 1` → `w`.
  - Eligible only if `set_type = 'working'`, `load_type = 'external'`, `w > 0`, `1 ≤ reps ≤ 12`.
  - Exposure e1RM = max over eligible sets, else NULL. *(E-mod: Reynolds 2006, Halperin 2022)*
- **Exposure**: the latest non-deload session (completed or partial) with ≥1 logged working set of the slot's exercise.
- **Evaluable exposure** *(DC)*: all of the following hold, otherwise the exposure → **hold** and counts as neither success nor miss:
  - `load_modifier = 'none'` on its sets;
  - max `pain < 4`;
  - logged working sets ≥ prescribed working sets;
  - actual weight = prescribed weight ± 1 increment;
  - exercise not swapped.
- **Miss** (evaluable only): `set1_reps < rep_min` OR `Σ working reps < sets × rep_min`. *(DC; normal set-to-set rep drop near failure is not a miss, Refalo 2024)*
- **Early stop**: any set with `reps < rep_min` AND `actual_rir ≥ presc_rir + 2` → exposure non-evaluable; flag `early_stop`. *(DC)*
- **`min_set_reps`** = min `actual_reps` across the exposure's working sets.
- **`reps_needed(c)`** = `ceil(30 × ((c / last) × (1 + (rep_min + t)/30) − 1) − t)`, `t = target_rir`: reps at `last` that imply `rep_min` is achievable at load `c` with `t` in reserve. Round the inner value to 9 decimals before `ceil` to avoid float error. *(Epley arithmetic)*
- **RIR deadband**: never act on `|actual_rir − presc_rir| ≤ 1`. *(E-high: Halperin 2022)*

### 5.1 Next-session load (external load)
1. **No history, no baseline** → `presc_weight_kg = NULL` (calibration).
2. **Baseline only** → `round_load(0.9 × e1RM_baseline / (1 + (rep_min + target_rir)/30))`. *(PC)*
3. **Recalibrate** (sets `load_modifier = 'recalibrate'`). *(DC; ±3-rep deadband from Halperin)*
   - **When** any of:
     - the first exposure after calibration, a baseline, or a ≥56-day gap has `set1_reps ≥ presc_reps_max + 3` or `≤ rep_min − 3`;
     - any evaluable exposure has `set1_reps ≥ presc_reps_max + 3`;
     - last-set `actual_rir ≥ presc_rir + 3`.
   - **New load** `r = round_load(e1RM_x / (1 + (rep_mid + target_rir)/30))`, `rep_mid = floor((rep_min + rep_max)/2)`. `e1RM_x` may use the exposure's best set even above 12 reps.
   - **Bounds:** clamp `r` to ±20% of `last` on a first exposure; to `≤ last × 1.10` otherwise.
   - Downward case → use `r`. Upward case → `max(r, step-4 result)`; if `r ≤ last`, step 4 applies alone (including rep-extension).
4. **Increase** when the last evaluable exposure has every working set `actual_reps ≥ presc_reps_max` (the exposure's prescribed top; equals `rep_max` unless rep-extension is active) AND (last-set RIR not logged OR `actual_rir ≥ presc_rir − 1`). *(E-mod: ACSM 2009, Plotkin 2022; RIR gate DC)*
   - `k_max = max(1, floor(step_pct × last / inc))`.
   - For `k = k_max … 1`: `c = last + k × inc`; skip if `k ≥ 2` and `c > 1.10 × last`; accept the first `c` with `reps_needed(c) ≤ min_set_reps`.
   - A single increment is never blocked by the 10% cap. Never round a candidate down to `≤ last`.
   - **Rep-extension** if no `k` passes: `rn = reps_needed(last + inc)`.
     - `rn ≤ 30` → hold load; prescribe `presc_reps_max = rn`.
     - `rn > 30` → hold; flag `increment_too_coarse`.
     - *(E-mod: rep progression is a valid stimulus, Plotkin 2022)*
   - After an accepted increase, prescription returns to the slot's `rep_min–rep_max`.
5. **Miss handling.**
   - 1 miss → hold.
   - 2 consecutive evaluable misses at the same load → `round_load(last × 0.90)`, then reset the miss counter (only misses at the new load count). *(PC: Bell 2025 ~10%; reset DC)*
   - Non-evaluable exposures between two misses neither count nor reset.
6. **Otherwise hold.** Prescribed reps = `rep_min–rep_max` (or `rep_min–rn` under rep-extension) at `presc_rir`.

**Worked examples (must be unit tests):**

| Slot | Last exposure | Result |
|---|---|---|
| Barbell squat 6–10 @2, inc 2.5, step 5% | 100 kg, all sets 10 | 105 kg (k=2; reps_needed 8 ≤ 10) |
| Bench 8–12 @2, inc 2.5, step 2.5% | 60 kg, all sets 12 | 62.5 kg (reps_needed 10) |
| Leg press 8–12 @2, inc 5, step 5% | 200 kg, all sets 12 | 210 kg |
| DB curl 12–20 @2, inc 2/hand | 8 kg, all sets 20 | Hold; rep-extension to 23 |
| DB curl, next exposure | 8 kg, all sets 23 | 10 kg; range back to 12–20 |
| Cable pushdown 10–15 @1, inc 5 | 20 kg, all sets 15 | Hold; rep-extension to 21 |
| Lateral raise 12–20 @1, inc 2/hand | 4 kg, all sets 20 | Hold; `increment_too_coarse` (needs 34) |
| Any slot, 3 evaluable misses in a row at 100 kg | — | 90 kg after miss 2; miss 3 (at 90) does not cut again |

### 5.2 Bodyweight exercises
- Progress reps only; `rep_max` may go up to 30.
- Flag `rep_cap` after 2 consecutive evaluable exposures with all sets ≥ `rep_max`. *(E-mod: Plotkin 2022)*

### 5.3 Prescribed effort
- **Build weeks:** `presc_rir = target_rir`, constant within the block. *(E-high: periodization model doesn't change hypertrophy, Moesgaard 2022; constant RIR DC)*
- **Deload week:** `presc_rir = min(4, max(target_rir + 2, 3))`. *(PC: Bell 2023/2025)*
- **Gap first exposure:** `presc_rir + 1` (§5.4).

### 5.4 Modifiers (applied after 5.1)
**No stacking:** at most one load reduction per set; apply the single largest, never the product. *(DC)*

| Modifier | Sets | Load | RIR | `load_modifier` | Tag |
|---|---|---|---|---|---|
| Deload week | `ceil(sets/2)` | `round_load(last build load × 0.90)` | per 5.3 | `deload` | PC; E-low (deloads neutral for growth: Coleman 2024, Pancar 2026) |
| `d_ex` ≤ 13 days | — | no change | — | `none` | E-low (Coleman 2024; Hwang 2017) |
| `d_ex` 14–27 | — | × 0.95 | +1 | `gap` | PC/DC |
| `d_ex` 28–55 | −1 (min 1) | × 0.90 | +1 | `gap` | PC/DC; E-mod (Bosquet 2013) |
| `d_ex` ≥ 56 | −1 (min 1) | × 0.80; ≥ 180 days → NULL (calibrate) | +1 | `gap` | PC/DC; E-low (Halonen 2024) |
| Agent `reduce_load` | — | × 0.90 | — | `review_reduce` | DC |

- `d_ex` = days since this exercise's last completed exposure.
- **Fast return:** after a `gap` exposure, if the next evaluable exposure meets the step-4 trigger, next load = `max(step-4 result, min(pre_gap_load, last × 1.10))`. *(E-low: Halonen 2024; DC)*
- **Global gap** `d_any` (days since last completed session): 14–20 → resume the block where it stopped; ≥ 21 → re-plan trigger (§6.1), no session generated until the new block exists. *(DC)*
- **Exclusions:** any slot whose exercise or pattern matches an active `limitation` is dropped.

### 5.5 Session sequencing
Sessions run through `(week, day_index)` in order. A skipped session is marked `skipped`; the next one is generated. After the last session of the deload week → block `completed` → block-plan trigger.

### 5.6 Volume accounting
- Fractional weekly sets per muscle = `Σ (slot sets × exercise_muscle.weight)` over build-week slots. *(E-mod: Pelland 2025)*
- Achieved sets = same sum over logged working sets.

### 5.7 Flags emitted to summaries (§6.3)

| Flag | Rule | Tag |
|---|---|---|
| `stalled` (exercise) | (a) e1RM-eligible: best exposure e1RM not ≥ 1% above prior best for 4 consecutive evaluable exposures; (b) otherwise: no load increase and no rise in total reps at that load for 4 evaluable exposures; (c) or 2 miss-reductions within 42 days | PC/DC |
| `increment_too_coarse` | §5.1 step 4, `rn > 30` | DC |
| `rep_cap` | §5.2 | E-mod |
| `early_stop` | §5.0 | DC |
| `fatigue` (session) | Build weeks: ≥ 2 slots with evaluable misses in the same week, OR ≥ 2 exercises with exposure e1RM ≥ 5% below block best on 2 consecutive exposures | PC; thresholds DC |
| `pain_recurrent` | Same exercise with pain ≥ 4 in ≥ 2 sessions within 14 days | DC |
| `red_flag` | Session note matches the red-flag keyword list (§6.5 S4) | PC + DC |
| Per-muscle status (block end) | **progressing:** any 1.0-weight exercise for the muscle improved best e1RM vs last block, progressed reps-at-load, or has `rep_cap`. **stalled:** not progressing for 2 consecutive blocks AND adherence ≥ 0.9 AND no pain ≥ 4 AND no reductions. **overreached:** ≥ 50% of the muscle's direct slots had a reduction, OR adherence < 0.8, OR `pain_recurrent` | DC |
| `volume_suggestion` (advisory) | progressing → hold; stalled → `+max(2, round(0.2 × weekly_sets))` up to soft max; overreached → `−max(2, round(0.2 × weekly_sets))` down to hard min. Two raises in a row without progress → `volume_ceiling_reached`; stop raising | E-mod hold-when-progressing (Barsuhn 2024, Camargo 2026); thresholds DC |

## 6. Agent

### 6.1 Triggers
| Trigger | Call |
|---|---|
| Onboarding complete | `block_plan` |
| Block completed | `block_plan` |
| `d_any` ≥ 21 days, limitation added, or goal/equipment/days/minutes changed | `block_plan` (current block → `abandoned`) |
| Completed session has any of: pain ≥ 4, a note, a miss, `early_stop`, an unplanned exercise, `fatigue`, `pain_recurrent`, `red_flag` | `session_review` |

Pain 1–3 is logged and summarized but does not call the LLM. Otherwise the engine generates the next session with no LLM call.

### 6.2 Allowed actions
- `block_plan`: choose split, exercises, sets, rep ranges, target RIR for the block's build weeks (engine applies deload).
- `session_review`: per slot, one of `swap`, `drop_set`, `drop_slot`, `hold_load`, `reduce_load` (engine applies ×0.90). Scope: `next_session` or `rest_of_block`. Never increase load.

### 6.3 Inputs (built by code)
- Profile (incl. tier, priority muscles), active limitations, available equipment with increments.
- Exercise candidates, **pre-filtered** by equipment and exclusions, each with `exercise_muscle` rows, effort class, `stretch_bias`.
- Per muscle: planned and achieved weekly fractional sets (last block), status, `volume_suggestion`, `volume_ceiling_reached`, tier-default target (§6.5 table).
- Per exercise: last 3 exposures (date, top set weight × reps @ RIR), best e1RM this block and last block, consecutive misses, max pain last 14 days, adherence (completed / prescribed working sets), `d_ex`, all §5.7 flags.
- Last block's template with estimated minutes per day.
- For `session_review`: the session's sets (prescribed vs. actual, `load_modifier`, pain), notes, triggering flags.
- Never raw full history.

### 6.4 Output schemas

`block_plan`:
```json
{
  "rationale": "string, <=120 words",
  "days": [
    {"day_index": 0, "slots": [
      {"exercise_id": 12, "sets": 3, "rep_min": 6, "rep_max": 10, "target_rir": 2}
    ]}
  ]
}
```

`session_review`:
```json
{
  "adjustments": [
    {"slot_id": 41, "action": "swap", "new_exercise_id": 18,
     "scope": "rest_of_block", "reason": "string"}
  ],
  "message": "string"
}
```
`action` ∈ {`swap`, `drop_set`, `drop_slot`, `hold_load`, `reduce_load`}; `new_exercise_id` present only for `swap`.

### 6.5 Validation (code)

`block_plan` checks use build weeks. Tier-A muscles = chest, back, quads, hamstrings, glutes, side_delts.

| ID | Rule | On fail | Tag |
|---|---|---|---|
| V0 | Exercise IDs exist and are in the candidate list; `len(days) == days_per_week` | reject | — |
| V1 | Tier-A weekly fractional sets ≥ 4 (warn instead if no candidate can train that muscle) | reject | E-mod (Pelland 2025 MED ≈ 4) |
| V2 | Tier-A weekly ≥ 10 (novice ≥ 6) | warn | E-high (ACSM 2026) |
| V3 | Any muscle > soft max → warn; > 24 → reject | warn / reject | PC; hard cap DC |
| V4 | Per session per muscle: > 11 → reject; > 8 → warn | reject / warn | E-low (Remmert 2025 preprint; Krieger 6–8) |
| V5 | Each Tier-A muscle ≥ 1.0 fractional on ≥ 2 distinct days; non-Tier-A muscle with ≥ 6/wk on only 1 day → warn | reject / warn | E-high (ACSM 2026 ≥ 2×/wk) |
| V6 | Sets per slot outside 1–6 → reject; 1 or 6 → warn | reject / warn | PC |
| V7 | `rep_min ≥ 5` unless goal = strength; `rep_max ≤ 30`; `2 ≤ rep_max − rep_min ≤ 8` | reject | E-high (Lopez 2021); span DC |
| V8 | External-load compound `rep_max` > 15 → reject; > 12 → warn. Isolation `rep_max` > 20 → warn | reject / warn | E-mod (Reynolds 2006, Halperin 2022) |
| V9 | Goal ∈ {hypertrophy, general}: `target_rir` 0–3 (reject). Class range warn: HEAVY 1–3, COMPOUND 1–3 (stable 0–3), ISOLATION 0–2 | reject / warn | E-mod (Robinson 2024, Refalo 2024); class split PC |
| V10 | `est_min = 6 + Σ sets × m + n_slots + 2 × max(0, n_compound_slots − 1)`, `m` = HEAVY 3.25, COMPOUND 2.75, ISOLATION 2.0. Reject if `est_min > 1.1 × session_minutes` or working sets per day > 30 | reject | PC; `m` DC |
| V11 | 3–8 slots per day | warn | PC |
| V12 | Coverage, warn only if an eligible candidate exists: no leg curl; no side-delt isolation; no overhead triceps extension; no calf raise; no leg extension | warn | E-low (Plotkin 2023; Maeo 2021, 2023) |
| V13 | Weekly pull sets ≥ 0.9 × push sets | warn | PC |
| V14 | Isolation/core slot before a compound on the same day; barbell squat and hinge adjacent with `target_rir ≤ 2` | warn | E-mod (order irrelevant for growth, Nunes 2021) |
| V15 | Vs previous block: < 60% of exercises kept (excluding limitation removals); > 1 compound changed per day; a progressing exercise rotated out | warn | E-low (Kassiano 2022) + PC |
| V16 | Every slot's exercise has `exercise_muscle` rows | reject | DC |

`session_review` checks:

| ID | Rule | Tag |
|---|---|---|
| S1 | `slot_id` belongs to the active block. Swap target is a candidate with the same `movement_pattern`; for `isolation`/`core` it must also have an identical set of 1.0-weight muscles | DC |
| S2 | Pain 4–5 on a slot → action ∈ {`hold_load`, `reduce_load`, `swap`, `drop_set`}. Pain ≥ 6 → {`swap`, `drop_slot`}. `pain_recurrent` → scope `rest_of_block` | PC (Silbernagel 2007 pain-monitoring; traffic-light bands); cut-points DC |
| S3 | Never increase load | — |
| S4 | `red_flag` keyword match in notes (numb, tingl, weak, night pain, swell, lock, giving way, pop, tear, chest pain, dizz, faint, bladder, bowel) → code drops affected slots for the next session regardless of agent output and shows a fixed "see a qualified clinician" message. Agent message must not diagnose | PC + DC |

Failure handling:
- Rejects: retry once with errors appended. Second failure → log `rejected` and fall back:
  - `block_plan`: repeat the previous block's template (or stop and ask if none exists).
  - `session_review`: no adjustments, except slots with pain ≥ 4 are dropped for the next session.
- Warnings never trigger a retry; store in `agent_call.warnings` and show with the rationale.
- Every call (accepted or not) is written to `agent_call`.

## 7. Onboarding (v1: deterministic form, CLI prompts)

Required: goal, training age (months), days per week, session minutes, available equipment with increments, limitations (may be none; each mapped to an excluded pattern or exercise; disliked exercises are entered as limitations).

Optional: priority muscles, sex, birth year, height, bodyweight, baselines (recent best set per exercise: weight × reps @ approx. RIR).

Cold start: exercises without a baseline get calibration sessions (§5.1 step 1). Self-reported baselines are discounted 10% and recalibrated after the first exposure (§5.1 steps 2–3).

## 8. Defaults (reversible)

- kg storage. RIR optional, but the UI prompts for it on the **last working set** of each slot. *(E-mod: Halperin 2022)*
- Double progression with relative steps, Epley range guard, and rep-extension.
- Constant target RIR within a block; deload RIR ≥ 3; deload never full rest.
- Fractional set counting (1.0 / 0.5).
- Pain scale 0–10; LLM review at pain ≥ 4.
- Per-exercise gap thresholds; re-plan at 21 days.
- Rest timer shown per class (display only): HEAVY 150 s, COMPOUND 120 s, ISOLATION 75 s, floor 60 s. *(E-mod floor, Singer 2024; values PC)*
- No tempo field.
- Agent runs only on triggers (§6.1), not after every session.

## 11. Decision process


- One-way decisions: jaekim03 decides.
- Two-way decisions: the builder picks the default, logs it, and continues.
- Any new decision that contradicts a locked one: stop and flag.
- One-way vs. two-way test: one-way if it changes stored-data shape (schema), involves external cost/hosting/platform/visibility, contradicts a locked decision, or changes behavior already relied on in logged workouts. Everything else is two-way.
- `config.py`: every engine threshold is a named constant with a `# D-<n>` comment.

- `.claude/agents/decision-auditor.md`: runs after each build step; reads the diff; reports conflicts with locked decisions or DESIGN.md. Report only, never decides.
- `.claude/commands/decisions.md` (`/decisions`): collects `open` one-way items, asks them as multiple choice, writes answers as `locked`.
- Decision entries contain no personal training information (D6).

## 12. Agent system prompt (coach)

Store verbatim at `prompts/coach_v1.txt`; `prompt_version = "coach-v1"`. Tier defaults in the prompt must match the §6.5 table (generate that part from `config.py` if they diverge).

```text
ROLE
You are an evidence-based hypertrophy coach for one lifter. You plan 4-week blocks
(3 build weeks + 1 deload) and review sessions that need interpretation. You choose
exercises, sets, rep ranges and target RIR. Code computes every load: never output a
load, percentage or e1RM. Return JSON only, matching the schema.

HARD CONSTRAINTS (code rejects violations)
- Exercises only from the candidate list. Swaps keep movement_pattern; isolation/core
  swaps also keep the same primary (1.0) muscles.
- Count weekly fractional sets: 1.0 per primary muscle, 0.5 per secondary (given per
  candidate). Chest, back, quads, hamstrings, glutes, side delts: >=4/week and trained on
  >=2 days. No muscle >24/week or >11 in one session.
- Build-week slots: target_rir 0-3, rep_min >=5, rep_max <=30, rep span 2-8, sets 1-6,
  estimated session time <= 1.1 x session_minutes. Deload changes are applied by code.
- Session review: never increase load. Pain 4-5 -> hold_load, reduce_load, swap or
  drop_set. Pain >=6 -> swap or drop_slot. Recurrent pain -> scope rest_of_block and
  suggest the user add a limitation. Never diagnose.

WHAT THE EVIDENCE SAYS (strongest first; cite author-year when you use it)
1. Weekly hard sets per muscle drive growth with diminishing returns: most gain by ~10,
   still worthwhile 10-20, little per set beyond ~20 (Pelland 2025; ACSM 2026).
   Trained lifters grow as well holding ~12-18 sets as adding many more (Barsuhn 2024;
   Camargo 2026). Do not add volume to someone who is progressing.
2. Effort: end sets at 0-3 RIR. 1-2 RIR grows about as well as failure with less
   fatigue (Robinson 2024; Refalo 2024). Failure is for the last set of isolation or
   machine work, not heavy barbell squats or hinges.
3. Load is flexible: ~5-30 reps all grow muscle near failure (Lopez 2021; ACSM 2026).
   Heavier compound work (<=10 reps) adds strength.
4. At equal volume, frequency, split, exercise order and periodization model barely
   matter for growth (Pelland 2025; Ramos-Campo 2024; Nunes 2021; Moesgaard 2022).
   Use them to fit volume into the schedule and to keep each session <=8 sets/muscle.
5. Rest >=60 s; beyond ~90 s adds little growth (Singer 2024). Tempo 0.5-8 s/rep is
   equivalent; never prescribe >10 s reps (Schoenfeld 2015).
6. Full ROM by default. Lengthened partials ~ full ROM (Wolf 2025). Long-muscle-length
   variants are a LOW-certainty tie-breaker (Wolf 2025 review; Varovic 2025 found
   trivial differences). Prefer stretch_bias candidates only when otherwise equal.
7. Compounds leave gaps: squats/hip thrusts barely grow hamstrings (Plotkin 2023);
   presses miss side/rear delts; overhead triceps work beat pushdowns (Maeo 2023);
   seated beat lying leg curls (Maeo 2021).
8. Machines ~ free weights for growth (Haugen 2023). EMG and pump do not predict
   growth: never justify a choice with them.
9. Deloads neither add nor cost growth (Coleman 2024; Pancar 2026). 1-2 weeks off
   costs little; lost size returns quickly (Halonen 2024).
10. Conventions, not evidence (label them as such if used): MEV/MAV/MRV landmarks,
   weekly +1-2 set ramps, RIR ramps, 3-4 week accessory rotation, push:pull >=1.

BLOCK PLANNING
1. Read the summaries: tier, days, minutes, equipment, limitations, priority muscles,
   per-muscle status and volume_suggestion, per-exercise flags, last block's template.
2. Split by days (default; deviate only with a stated reason): 2 = full body x2;
   3 = full body x3 (or FB/upper/lower); 4 = upper/lower x2; 5 = U/L/push/pull/legs;
   6 = push/pull/legs x2.
3. Weekly fractional sets per muscle: start from last block, adjusted by
   volume_suggestion; on a first or post-gap block use tier defaults:
   chest 8/12/14, back 10/14/16, quads 8/12/14, hamstrings 6/10/12, glutes 6/8/10,
   side delts 6/10/12, rear delts 4/6/8, biceps 6/10/12, triceps 6/10/12,
   calves 6/8/10, abs 4/6/8, front delts 0 direct (novice/intermediate/advanced).
   Hold if progressing; +~20% (>=2 sets) only if stalled with good adherence and no
   pain; -~20% if overreached; stop raising after two raises without progress.
   Priority muscles may sit toward the upper end, within soft max.
4. Distribute: every major muscle on >=2 days, <=8 fractional sets per session.
5. Exercises: one main compound per pattern, then fill gaps (leg curl - seated if
   available; leg extension; lateral raise; rear fly/face pull; overhead triceps
   extension; curl; full-stretch calf raise). Prefer stable, comfortable, finely
   loadable options.
6. Order: main compound first, secondary compounds, isolation, calves/core last.
   A priority muscle may lead.
7. Rep ranges and RIR: barbell squat/hinge 6-10 @2; other compounds 8-12 @2
   (machines/cables @1); isolation 10-15 or 12-20 @1. Typically 2-4 sets per slot.
   Keep external-load compounds at rep_max <=12 so progress can be tracked.
8. Carry-over: keep >=60% of exercises and every exercise still progressing; change
   <=1 compound per day; rotate 1-3 accessories when stalled, rep_cap,
   increment_too_coarse, pain or boredom. For increment_too_coarse, pick a heavier rep
   range or a finer-increment variant (cable/machine).
9. Short on time: trim abs, calves, rear delts, direct front delts, glutes, then arms,
   then major muscles. Never take a major muscle below 4.
10. Rationale (<=120 words): split, weekly sets for each major muscle, what changed
   versus last block and why, pain-driven changes, and the confidence of any
   non-obvious choice.

SESSION REVIEW
- One miss: no action (code holds). Two misses: code reduces; consider a swap only
  if the exercise is stalled.
- early_stop or a time/equipment note: no adjustment; acknowledge it.
- fatigue flag: drop_set + reduce_load, scope next_session (a one-session deload).
- Pain 1-3 that settles: no change. Pain 4-5: hold_load or reduce_load next_session,
  or swap to a tolerated variant (different implement, grip, angle or ROM). Pain >=6,
  pain that changed technique, or recurring pain: swap or drop_slot for rest_of_block
  and suggest recording a limitation. Pain that persists or worsens week to week ->
  recommend seeing a clinician.
- red_flag: code drops the slots; your message tells the user to see a qualified
  clinician and contains nothing diagnostic.
- Unplanned exercise: acknowledge it; consider it at the next block if it fits.
- stalled: no in-block change unless pain; plan a rotation or rep-range change at the
  next block.

COMMUNICATION
Be brief and specific, with numbers first. Label evidence vs convention. State
uncertainty plainly: most data come from young, mostly male lifters over 8-12 weeks.
Never promise results, never prescribe complete rest for mild pain, and never
diagnose.
```

### 13.2 Privacy guard (D6)

**Personal training information** = anything from jaekim03's real use of the app:
- the database file or any copy, dump or export of it;
- profile values (bodyweight, height, birth year, sex, training age, goal, priority muscles);
- baselines, logged sets, loads, reps, RIR, pain scores, session notes;
- limitation and injury descriptions;
- block plans, rationales and review messages generated for him;
- `agent_call` inputs/outputs, LLM transcripts, filled-in prompts or summaries;
- screenshots or recordings showing real data.

Data derived from real data ("anonymized" copies) counts as personal.

**Allowed on GitHub:** code, DESIGN/DECISIONS/research docs, prompt templates, generic exercise seed data, synthetic test data.
